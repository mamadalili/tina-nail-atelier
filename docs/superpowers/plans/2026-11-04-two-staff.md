# Independent Tina and Sonia schedules

**Goal:** Let guests select Tina or Sonia and let the existing manager view, edit and close/reopen each person's calendar independently. The owner explicitly chooses initially open hours for both.

**Architecture:** Add a validated `staff` identifier (`tina`, `sonia`) to appointments, blocks and receipts. Scope active-slot uniqueness and availability by staff. Preserve existing appointments/closures as Tina, original request hashes/references, and the current manager account. The public UI and manager each select one person; editing can deliberately reassign an appointment with collision checks. Keep the Node/PostgreSQL reservation contract consistent with the shared-host runtime.

**Design:** Reuse the current two-option selection style and a clear person selector above the manager calendar. Keep the selected name in day headings, booking recaps and the final receipt. No new photos or credentials.
